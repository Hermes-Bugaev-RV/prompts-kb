## Запрос конкретной задачи

Твоя задача — написать универсальный, переиспользуемый и чистый фрагмент кода на языке C, который реализует основную функцию обработки входящих данных, для конечного автомата состояний (FSM).

Необходимая функция вызывается для каждого принятого байта. Функции выполняющие определенные команды дисплея уже реализованы в соответствующем модуле их нужно только вызвать в нужном месте.

### Описание конечного автомата состояний (FSM - Finite State Machine)

Предназначен для интерпретации команд управления дисплеем малого разрешения, поступающих через последовательный интерфейс. Модуль обеспечивает надежную обработку потока байтовых данных и их преобразование в вызовы соответствующих функций управления дисплеем.

Конечный автомат включает следующие основные состояния:

* IDLE - Ожидание начала новой команды. В этом состоянии FSM ожидает получения стартового байта или синхронизирующей последовательности.
* HEADER_PARSING - Обработка заголовка команды. Включает извлечение кода операции, определение длины сообщения и предварительную валидацию.
* PARAM_LENGTH_PARSING - Определение количества параметров команды. Для команд с переменным числом параметров сначала читается их количество.
* PARAM_DATA_PARSING - Последовательное чтение параметров команды. Состояние поддерживает счетчик прочитанных параметров и их типизацию.
* CHECKSUM_VALIDATION - Проверка целостности принятого сообщения с использованием контрольной суммы или CRC.
* COMMAND_EXECUTION - Выполнение распознанной команды через вызов соответствующей функции дисплея.
* ERROR_HANDLING - Обработка ошибок протокола или выполнения команд. Включает формирование сообщений об ошибках.

### Структуры данных

```cpp

// Перечисление состояний FSM
typedef enum {
    FSM_STATE_IDLE = 0,
    FSM_STATE_HEADER_PARSING,
    FSM_STATE_PARAM_LENGTH_PARSING,
    FSM_STATE_PARAM_DATA_PARSING,
    FSM_STATE_CHECKSUM_VALIDATION,
    FSM_STATE_COMMAND_EXECUTION,
    FSM_STATE_ERROR_HANDLING
} fsm_state_t;

// Коды команд протокола
typedef enum {
    CMD_INIT_DEVICE = 0x01,           // Инициализация дисплея
    CMD_DEINIT_DEVICE = 0x02,         // Деинициализация дисплея
    CMD_SET_ACTIVE = 0x03,            // Установка активности
    CMD_SET_FREQUENCY = 0x04,         // Установка частоты обновления
    CMD_SET_FORMAT_STRING = 0x05,     // Сохранение строки формата
    CMD_SET_FORMAT_PARAMS = 0x06,     // Сохранение параметров формата
    CMD_ALLOC_MEMORY = 0x07,          // Выделение памяти для строк
    CMD_FREE_MEMORY = 0x08,           // Освобождение памяти
    CMD_PRINTF_TO_ROW = 0x09,         // Формирование строки дисплея
    CMD_SET_ROW_MAPPING = 0x0A        // Назначение строки дисплея
} command_code_t;

// Структура контекста FSM
typedef struct {
    fsm_state_t         current_state;    // Текущее состояние
    command_code_t      current_command;  // Текущая обрабатываемая команда
    uint8_t             param_count;      // Количество параметров команды
    uint8_t             params_received;  // Количество принятых параметров
    uint16_t            expected_length;   // Ожидаемая длина сообщения
    uint8_t             checksum;          // Текущая контрольная сумма
    display_dev_for_fsm_t* display_device; // Указатель на устройство дисплея
} display_fsm_context_t;

```

### Протокол связи

Формат сообщения
Каждое сообщение протокола имеет следующую структуру:

    [SYNC] [CMD] [LEN] [DATA...] [CHECKSUM]

* SYNC (1 байт): Синхронизирующий байт 0xAA для определения начала сообщения
* CMD (1 байт): Код команды из перечисления command_code_t
* LEN (1 байт): Длина поля данных (0-252 байта)
* DATA (0-252 байта): Данные команды, структура зависит от типа команды
* CHECKSUM (1 байт): Контрольная сумма XOR всех предыдущих байтов

## Инструкция к выполнению задания

1. Выбери распространённый, но полезный сценарий программирования.
2. Напиши чистый, переносимый код с корректными заголовками, комментариями и минимальной, но полезной обработкой ошибок.
3. Отметь, какие особенности языка ты используешь (например, RAII в C++, арифметика указателей в C, структуры, умные указатели и т.д.).
4. В верхней части кода добавь блочный комментарий с описанием, ограничениями и инструкцией по использованию.
5. По желанию — предложи идеи по расширению или улучшению кода для более продвинутого применения.

Результат должен содержать:

- Блочный комментарий с описанием и инструкцией по использованию
- Полный код (желательно до 100 строк, но завершённый)
- Встроенные комментарии, объясняющие логику
- При необходимости — заметки по адаптации под встроенные системы, Linux или Windows
